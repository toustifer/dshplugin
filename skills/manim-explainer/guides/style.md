# 配色、排版与动画节奏规范

Manim 动画的核心目的不是为了酷炫，而是为了**用空间位置与时序变化降低理解阻力**。混乱的配色、过快的节奏或拥挤的文字会把认知负荷成倍放大。

---

## 1. 调色板基准（暗色沉浸）

项目在 `mcp__manim__style_guide` 中维护着唯一的官方调色板。严禁在代码中随意输入 RGB 乱码或纯白纯红，一律映射为语义色：

| 语义色常量 | Hex 编码 | 含义与使用场景 |
|---|---|---|
| `background` | `#0E1116` | 画布背景（深蓝近黑），提供高反差与舒适夜间感 |
| `C_BLUE` | `#58C4DD` | 正向概念、默认数据节点、输入层、基准线 |
| `C_HIGHLIGHT` | `#FFD166` | 聚焦点、当前激活的计算节点、注意力权重、公式高亮 |
| `C_GREEN` | `#7BE495` | 最终输出结果、收敛成功态、正确方案对照 |
| `C_RED` | `#FF6B6B` | 负权重、错误做法、损失惩罚、阻断态 |
| `C_GREY` | `#5A6472` | 未激活的休眠神经元、辅助网格、次要说明文字 |
| `C_EDGE` | `#8A94A6` | 连接线、数据流动通道、次级提示标注 |

## 2. 字体与排版层级

画面元素必须有明确的视觉重心，遵循以下三层字号规范：

- **标题层（Title）**：`44 pt`
  - 放置于顶部：`.to_edge(UP, buff=0.6)`
  - 文字简练（通常不超过 12 个汉字），直击本画面解释的核心概念。
- **正文层（Body）**：`32 pt`
  - 坐标轴关键刻度、核心节点标签、中间推导结果。
- **说明层（Note / Caption）**：`24 pt`
  - 位于底部说明区：`.to_edge(DOWN, buff=0.7)`
  - 或者紧贴对象：`.next_to(target, DOWN, buff=0.25)`
  - 动态随着计算步骤切换文字（使用 `Transform(caption, new_caption)`）。

### 中文字体保底
Windows 系统下首选字体列表：
1. `"Microsoft YaHei"`（微雅黑，全平台最稳，字符集齐全）
2. `"Microsoft YaHei UI"`
3. `"SimHei"`（黑体）
4. `"Source Han Sans SC"`（思源黑体，若系统安装）

## 3. 动画节奏律动（Pacing）

人类视觉认知有反应延时，动画节奏切忌机械均速。

1. **出场次序**：
   - 永远遵循 **背景/框架先行 → 主体节点铺设 → 连接与流动贯通 → 聚焦突出演算**。
   - 多个同级元素出场必须使用 `LaggedStart(*anims, lag_ratio=0.1~0.15)` 产生波浪感，不要一瞬间全部闪现。
2. **动作时长控制**：
   - 文字写出 (`Write`)：`0.8 ~ 1.2 秒`
   - 物体淡入/位移 (`FadeIn`, `Shift`)：`0.6 ~ 0.8 秒`
   - 强调点亮 (`Indicate`, `Flash`)：`0.6 ~ 1.0 秒`
   - 信号流动 (`ShowPassingFlash`)：`1.0 ~ 1.5 秒`
3. **关键定格与尾部留白**：
   - 在关键状态变换（例如隐藏层神经元全部点亮后），必须调用 `self.wait(0.8 ~ 1.2)` 留出脑中消化时间。
   - 动画结尾必须保留 `self.wait(0.5 ~ 0.8)`，严禁最后一帧动作刚做完视频就截断黑屏。
